# 0027. Лента Activity, «Deliverables this month» и прогресс продуктов

Статус: принято, 2026-10-20

## Контекст

Главная арт-директора из Figma («SCREEN:h_ad Art Director view») показывает Latest activity: кто что сделал в съёмках («Odina uploaded new files», «Amina left a comment», «Shoot 02 marked as completed»). Позже появится отдельная страница Activity с той же лентой. Журнала событий в системе не было, а уведомления (ADR 0020) для этого не подходят: они адресованы одному человеку, склеиваются, пока не прочитаны, и их можно удалить через Clear all.

Ещё на главной есть KPI «Deliverables this month» и прогресс на карточках продуктов. Для KPI не хватало времени отправки, для прогресса — счётчиков в списке продуктов.

## Решения

### Лента — отдельная таблица событий

```
activity_events   id, type, actor_id?, subject_id?, shoot_id, product_id?, deliverable_id?,
                  comment_id?, count, created_at
```

- Одна строка на событие, без рассылки копий по получателям: видимость считается при чтении. Если человека убрали из команды съёмки, он сразу перестаёт видеть её события, переписывать ничего не нужно.
- Колонки типизированные, без jsonb. Удаление съёмки, deliverable или комментария убирает их события через ForeignKey (CASCADE). Удалённый аккаунт оставляет событие без автора (SET NULL). Названия не копируются: лента показывает текущие.
- Типы и место записи (в той же транзакции, что и действие, `app.activity.service.record`):
  - `shoot_created` — создание съёмки;
  - `version_submitted` — Submit for review, `count` — файлов в версии;
  - `version_approved` и `changes_requested` — решение арт-директора, `subject_id` — автор версии;
  - `content_sent` — Send to brand, `count` — отправленных файлов;
  - `shoot_completed` — отправлен последний deliverable съёмки, то есть её статус стал completed (ADR 0007);
  - `content_commented` — комментарий на странице контента, `comment_id`; удалённый комментарий пропадает из ленты;
  - `content_approved` — одобрение брендом, `count` — файлов.
- Каждое событие принадлежит съёмке. Видимость:
  - арт-директор и креатор видят события съёмок, где они арт-директор или в команде;
  - бренд видит только то, что дошло до него (`content_sent`, `content_commented`, `content_approved`), по своим продуктам.
- Индекс `(shoot_id, created_at)` обслуживает ленту, `product_id` — ленту бренда. `actor_id` и `subject_id` проиндексированы, чтобы удаление пользователя не сканировало таблицу.

### API

`GET /api/activity?limit=&cursor=` (limit до 50, по умолчанию 20). Возвращает события, новые первыми, и `next_cursor`. Пагинация по курсору (`created_at`, `id`): новое событие не сдвигает следующую страницу, как сдвинул бы offset. В строке: тип, время, `actor`, `subject`, `shoot` (бренду — `None`: съёмку он не видит, как и на странице Content), `product`, `deliverable` (id и текущее название), начало комментария (до 140 символов) и `count`. Число запросов не зависит от размера страницы.

Текст строки собирает фронт по типу. Свои действия он пишет как «You …».

### Deliverables this month

- У `shoot_deliverables` появилось `sent_at`, его ставит Send to brand.
- У `GET /api/tasks` появился фильтр `sent_since` (время с часовым поясом): только отправленные бренду не раньше этого момента.
- KPI — это `total` запроса `status=approved&sent_since=<начало месяца>`. Начало месяца клиент берёт в своём часовом поясе.

### Прогресс на карточке продукта

`ProductListItem` получил `deliverables` и `approved`. Это deliverables продукта, видимые пользователю (те же правила, что на странице продукта: арт-директору свои, креатору — его арт-директоров, бренду все), и сколько из них approved по правилу ADR 0018: хоть один deliverable съёмки отправлен бренду. Считается одним запросом на страницу.

### Миграция

- `sent_at` у уже отправленных deliverables заполняется временем появления их файлов на Content.
- Ленту миграция заполняет из того, что уже есть в базе: съёмки, отправленные и проверенные версии, отправки, одобрения и комментарии, завершённые съёмки.
- `downgrade` удаляет таблицу и колонку.

## Не входит в эту итерацию

Страница Activity с фильтрами, события изменения съёмки и продукта, назначения бренда (они есть в уведомлениях), чистка старых событий.

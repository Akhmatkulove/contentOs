# 0020. Уведомления о назначении

Статус: принято, 2026-10-20

## Контекст

Бренд назначает арт-директору заказы (deliverables продукта, ADR 0004), но арт-директор узнавал о них только сам, на странице продукта или в бэклоге (ADR 0019). Колокольчик («Notification button / Unread» из Figma) уже стоял на страницах, но ничего не открывал, а точка горела всегда. Панели уведомлений в Figma нет.

## Решения

### Модель

```
notifications   id, user_id, type (deliverables_assigned), actor_id?, product_id?, count,
                created_at, read_at?
```

- Тип пока один: `deliverables_assigned`. Колонки типизированные, без jsonb, чтобы удаление продукта или аккаунта чистило их через ForeignKey (`product_id` CASCADE, `actor_id` SET NULL).
- **Одно уведомление на продукт.**
  - Когда бренд сохраняет продукт с новыми deliverables (создание или редактирование, `products.service._add_deliverables`), каждый назначенный арт-директор получает уведомление, где `count` — сколько deliverables назначено на него.
  - Если о том же продукте уже есть непрочитанное уведомление, новое назначение не создаёт второе, а увеличивает `count` и поднимает его наверх (`created_at`). Прочитанное остаётся как было, и следующее назначение начинает новое.
- Уведомление создаётся в той же транзакции, что и сохранение продукта.
- Если бренд убрал у арт-директора все deliverables продукта, его непрочитанное уведомление об этом продукте удаляется (`forget_unassigned`). Иначе следующее назначение прибавилось бы к уже снятым.

### API

- `GET /api/notifications?limit=` (до 50, по умолчанию 20) — последние уведомления, новые первыми, и `unread` — число непрочитанных всего. В строке: кто сделал (бренд), продукт с первым фото, `count`, `read`.
- Видимость: уведомление о назначении видно, пока на пользователе есть deliverable этого продукта. Если связку с брендом сняли или бренд убрал все его deliverables, уведомление пропадает вместе с доступом к продукту.
- `POST /api/notifications/{id}/read` — прочитано одно, чужое отвечает `404`. `POST /api/notifications/read` — Mark all as read. Оба отвечают `204`.

### Интерфейс

- Виджет `widgets/notification-bell` (`NotificationBell`) заменил статичный `VNotificationButton unread` на всех страницах и в мобильном топбаре. Точка горит только при непрочитанных.
- По клику открывается поповер в стиле выпадающих списков: «Acme assigned you 3 deliverables in Black Abaya», время («5 min ago», «Yesterday»), точка у непрочитанных, Mark all as read.
- Клик по уведомлению отмечает его прочитанным и открывает бэклог с этим продуктом: `/tasks?view=brand&product=…`. Там видны именно эти заказы и сразу есть Plan shoot (ADR 0019).
- Обновление: при возврате фокуса на вкладку и раз в минуту. Запрашивается только для одобренного пользователя.
- API, ключи кэша и текст живут в самом виджете, отдельной сущности нет: у них один потребитель, а Steiger (`insignificant-slice`) требует не выделять такой слайс.

## Не входит в эту итерацию

Telegram как второй канал, отметка «New» на продукте, уведомления других типов (решение по версии, отправка бренду, назначение креатора), push в реальном времени, настройки уведомлений, страница всех уведомлений и макет панели.

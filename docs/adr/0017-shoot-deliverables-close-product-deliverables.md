# 0017. Deliverable съёмки закрывает deliverable продукта

Статус: принято, 2026-10-20

## Контекст

Deliverables бывают двух видов. Deliverable продукта — заказ бренда: что снять и на кого из арт-директоров (ADR 0004). Deliverable съёмки — работа команды: кто из креаторов снимает и по каким референсам (ADR 0007). До сих пор они не были связаны. На одного арт-директора в продукте бывает несколько заказов, и, создавая съёмку, он не мог указать, какой из них закрывает. Бренд тоже не мог увидеть, что по его заказу уже идёт работа.

## Решения

### Модель

```
shoot_deliverables.product_deliverable_id → deliverables.id  (ON DELETE SET NULL)
```

- Один deliverable съёмки закрывает ровно один заказ. Один заказ могут закрывать несколько deliverables, в том числе на разных съёмках: пересъёмка, два варианта.
- `product_id` остаётся у deliverable съёмки. Форма присылает и его, и заказ, и сервер проверяет, что заказ относится к этому продукту.
- NULL означает, что бренд убрал заказ из продукта (ADR 0005 удаляет убранные deliverables). Deliverable съёмки с работой остаётся на месте, только без заказа. У съёмок, созданных до этой миграции, связи тоже нет.

### Проверки в `POST` и `PUT /api/shoots` (`422`)

- Каждый deliverable съёмки присылает `product_deliverable_id` (`Pick the product deliverable`). Без заказа может остаться только сохранённый deliverable, чей заказ уже удалён. Снять связь формой нельзя.
- Новый для съёмки заказ должен быть назначен на арт-директора. Чужой и несуществующий заказ отвечают одинаково: `Product deliverable not found`. Заказы, которые эта съёмка уже закрывает, проходят без проверки назначения, как продукты и команда в ADR 0008: назначение могли снять после.
- Заказ должен относиться к продукту deliverable: `A deliverable's product deliverable is for another product`.

### `GET /api/shoots/product-deliverables?product_id=…`

Доступен только арт-директору (остальным `403`). Возвращает заказы, назначенные на него, в порядке внутри продукта. Можно ограничить продуктами: в форму передаются отмеченные продукты съёмки. У каждого заказа есть `shoots`: съёмки этого арт-директора, где он уже закрывает deliverable, по дате.

На странице съёмки у deliverable есть `product_deliverable` (`id`, `name`) или `null`.

### Интерфейс

- В Add deliverable первым идёт поле Product deliverable (на месте поля Product из Figma): «Продукт · заказ», а если заказ уже закрывает другая съёмка, ещё «· In Shoot 04». Выбор задаёт продукт и подставляет название, тип и срок заказа. То, что пользователь успел поправить руками после прошлого выбора, не перезаписывается.
- В таблице и карточках deliverables формы под продуктом написано «Closes <заказ>».
- Ключ кэша `shootKeys.productDeliverables(productIds)` лежит под `shootKeys.lists`, поэтому сохранение съёмки обновляет и подсказку «In Shoot …».

## Не входит в эту итерацию

Статус заказа, выведенный из deliverables съёмок (Not scheduled / Scheduled / In progress / Delivered), и прогресс продукта по нему. Бэклог незапланированных заказов у арт-директора. Уведомления о назначении. Создание съёмки начиная с выбора заказов. Запрет брендом удалять заказ, по которому идёт работа. «Closes …» на странице съёмки и в My tasks.

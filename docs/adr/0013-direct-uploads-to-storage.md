# 0013. Прямая загрузка файлов в хранилище

Статус: принято, 2026-10-14

## Контекст

Файлы контента (фото и видео продуктов, референсов, готового контента задач) шли через API: `POST /api/uploads` принимал multipart до 100 МБ и сам клал его в S3. Видео по 100 МБ занимают воркеры API и канал до него, а тело такого размера FastAPI читает ещё до проверки сессии. Хранилище позже станет Cloudflare R2.

## Решения

### Три шага

1. `POST /api/uploads` `{name, size, content_type}` — API проверяет заявленные тип (JPEG, PNG, WebP, MP4, MOV, WebM) и размер (фото до 15 МБ, видео до 100 МБ), заводит строку `files` с `pending = true` на временном ключе `uploads/<uuid>` и отдаёт presigned PUT URL (15 минут) с заголовками. Content-Type входит в подпись: с другим хранилище ответит 403.
2. Браузер кладёт файл прямо в хранилище (PUT), прогресс — от этого запроса.
3. `POST /api/uploads/{id}/complete` — API проверяет то, что реально лежит в хранилище: размер по HEAD, тип по первым байтам (как раньше, `app.files.media`). Фото скачивается и перекодируется в WebP без EXIF, видео копируется на постоянный ключ внутри хранилища (CopyObject, без скачивания). Временный объект удаляется. Не прошедший проверку файл удаляется вместе со строкой (413/422); если файла ещё нет — 409, строка остаётся. Повторный `complete` отдаёт тот же файл.

Пока файл `pending`, его нельзя взять в продукт, референс или задачу (`claim_files`). Брошенные загрузки (не дослали или не позвали `complete`) убирает ежедневная уборка, как и ничьи файлы.

### Почему presigned PUT, а не POST policy

POST policy умеет ограничить размер ещё в хранилище (`content-length-range`), но R2 её не поддерживает. Поэтому размер проверяется после загрузки, а ссылка короткая.

### R2

Нужны S3-эндпоинт `https://<account_id>.r2.cloudflarestorage.com`, регион `auto`, токен с Object Read & Write и CORS бакета: Origin фронта, методы PUT и GET, заголовок content-type (см. `.env.example`). HEAD, Range GET, CopyObject и presigned URL у R2 есть. MinIO локально пускает любой Origin.

### Фронт

`uploadFile` в `shared/api` делает все три шага; PUT идёт обычным axios — без базового URL и cookies API. Вызывающие (продукт, референс, задача) не изменились.

## Не входит

Фото профиля (`PUT /api/me/photo`, до 5 МБ) по-прежнему идёт через API. Multipart-загрузка частями для файлов больше 100 МБ и докачка после обрыва.

# 0014. Коллекции

Статус: принято, 2026-10-19

## Контекст

Коллекция у продукта и референса была свободным текстом (ADR 0003, 0004). Одну и ту же коллекцию набирали заново в каждой форме, опечатка или другой регистр давали «новую», а команда бренда не видела, какие коллекции уже есть.

## Решения

### Коллекция — запись с владельцем

```
collections   id, owner_id → users, name (до 100), created_at
              unique (owner_id, lower(name))
products.collection_id, references.collection_id → collections (SET NULL)
```

Владелец — тот, кто создал коллекцию. В API коллекция по-прежнему ходит именем: `collection` в запросах продукта и референса и в ответах.

### Кто видит

- Бренд — только свои.
- Арт-директор — свои и коллекции брендов, с которыми он в связке (ADR 0002).
- Креатор — свои, коллекции своих арт-директоров и их брендов.

Связка снята — чужие коллекции пропадают из списка, но у уже сохранённых продуктов и референсов остаются.

`GET /api/collections` — видимые коллекции `{id, name}` по алфавиту без учёта регистра.

### Выбор или создание по имени

При сохранении продукта или референса имя ищется среди видимых коллекций без учёта регистра: нашлась — берётся она («summer 26» выберет «Summer 26»), нет — создаётся новая с владельцем-автором. Так одинаковых коллекций не появляется: арт-директор, набрав имя коллекции бренда, получит её, а не свою копию.

Одно имя у разных владельцев всё же возможно: связку завели, когда у обоих уже была такая коллекция. Тогда в списке она одна, и выбирается своя, иначе самая старая.

Референс из продукта получает коллекцию продукта, как и раньше.

### Миграция

Строки становятся коллекциями владельцев: бренда у продукта, автора у референса; одно имя без учёта регистра у владельца — одна коллекция.

### Фронт

Поле Collection в форме продукта и в Add reference — `VCombobox`: ввод с подсказками из видимых коллекций и пунктом «Create "…"», если такой нет.

### Вкладка Collections в пуле референсов

`GET /api/references/collections` — коллекции с подходящими под поиск и фильтры референсами, по алфавиту, страницами по коллекциям; у каждой — сколько подходит и первые `preview` в выбранной сортировке. Одно имя без учёта регистра — одна коллекция. Референсы без коллекции на вкладку не попадают. `counts.collections` — сколько коллекций на вкладке.

Открытая коллекция — обычный список: `GET /api/references?collection=<имя>` (без учёта регистра), на счётчики вкладок не влияет.

## Не входит

Переименование и удаление коллекций, отдельная страница коллекций.

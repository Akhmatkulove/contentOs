# 0004. Deliverables и доступ арт-директора к продукту

Статус: принято, 2026-10-06

## Контекст

Бренд в создании продукта добавляет deliverables — единицы контента, которые нужно снять, — и на каждый назначает арт-директора. Назначенный арт-директор начинает работу с продуктом: продукт должен появиться у него в списке продуктов. ADR 0002 заранее решил, что бренд назначает на продукт только арт-директоров из своих связок, а снятие связки снимает и назначения.

## Решения

### Модель

```
deliverables   id, product_id, position, assignee_id?, name, brief?,
               status (to_shoot|in_progress|needs_changes|approved), due_date?
```

- Создаются вместе с продуктом в `POST /api/products` (поле `deliverables`, до 50), в той же транзакции, в порядке запроса.
- `assignee_id` обязателен в запросе и должен быть одобренным арт-директором из связок бренда (`brand_art_directors`), иначе `422` («Assignee is not the brand's art director»). Чужой арт-директор, креатор и несуществующий пользователь отвечают одинаково.
- В БД `assignee_id` nullable: при удалении аккаунта (`SET NULL`) или снятии связки deliverable остаётся у продукта без исполнителя.
- Бренду список его арт-директоров для поля Assignee отдаёт `GET /api/team/art-directors`.

### Доступ выводится из назначений

Арт-директор видит продукт, если на него назначен хотя бы один deliverable этого продукта. Отдельной таблицы «продукт → арт-директоры» нет: доступ всегда совпадает с назначениями, синхронизировать нечего. Если понадобится назначать арт-директора на продукт без deliverables, заведём таблицу тогда.

- `GET /api/products` для арт-директора — продукты с его deliverables, поиск и страницы те же, что у бренда. Креатор пока видит пустой список (продукты придут через съёмки).
- Снятие связки бренд ↔ арт-директор в админке обнуляет `assignee_id` у deliverables этого бренда с этим арт-директором: продукты бренда пропадают у него сразу (ADR 0002).

### Референсы продукта — в пуле арт-директора

По тому же правилу арт-директор видит в пуле референсы продуктов, где на него назначен deliverable: всё, что бренд добавил в продукт, попадает к исполнителю вместе с продуктом. Отдельных назначений референсов нет.

- `GET /api/references?search=&type=&product_id=&author_id=&tag=&sort=&scope=&page=&per_page=` (до 50 на страницу). Поиск без учёта регистра по названию, описанию, тегам и коллекции; тег — точное совпадение; `sort`: `newest` (по умолчанию), `oldest`, `title_asc`, `title_desc` (без названия — в конце). В ответе файлы (presigned URL) и имя автора — бренда.
- `GET /api/references/filters` — варианты фильтров Product, Creator и Tags: только то, что встречается в видимых пользователю референсах.
- Вкладки пула: `scope=all` (по умолчанию) и `scope=favorites` — только избранное пользователя. В ответе `counts` — размеры обеих вкладок под текущими поиском и фильтрами (один запрос), `total` — выбранной вкладки, для страниц. На фронте вкладка, поиск, фильтры, сортировка и страница живут в URL (`?tab=favorites&type=video&product=…&creator=…&page=2`).
- Избранное у каждого своё: `reference_favorites (user_id, reference_id)`. `PUT`/`DELETE /api/references/{id}/favorite` (204, повторный вызов ничего не меняет), в списке поле `favorite`. Добавить можно только видимый референс, остальные — `404`. Потеря доступа запись не удаляет: референс просто пропадает из списка.
- Снятие связки убирает и референсы: доступ к ним идёт через те же deliverables.
- Бренд страницы References не видит (маршрут только для команды), креатор пока видит пустой пул.

### Свои референсы

Арт-директор и креатор добавляют референсы в пул сами: `POST /api/references` (бренд — `403`, он создаёт референсы только в продукте). Автор — тот, кто создаёт; файлы — свои и ещё не использованные, как у продукта.

- Продукт необязателен и выбирается из тех, где на автора назначен deliverable (`GET /api/products/options` — все видимые продукты по названию). Чужой или несуществующий продукт — `422 «Product not found»`.
- Коллекция вводится свободным текстом, не берётся из продукта. `favorite: true` сразу кладёт референс в избранное автора.
- Видимость: свои референсы автор видит всегда. Референс с продуктом виден всем, кто видит референсы этого продукта (правило выше); без продукта — только автору.
- Поле Shoot в модалке пока выключено: съёмок нет.

### Интерфейс

Deliverables до создания продукта живут в памяти страницы, как черновики референсов, и уходят с продуктом по Create product. Создавать продукты может только бренд: маршрут `/products/new` закрыт для остальных ролей, кнопок Add product у них нет.

## Не входит в эту итерацию

Страница продукта и референса для арт-директора, фильтр по съёмкам, вкладка My references, коллекции в пуле, редактирование deliverables и смена исполнителя, статусы deliverables после создания, прогресс deliverables на карточке продукта, уведомление арт-директора о назначении.

# 0018. Статус deliverable продукта выводится из съёмок

Статус: принято, 2026-10-20

## Контекст

Бренд выбирал статус заказа (deliverable продукта, ADR 0004) вручную в форме продукта, и после создания этот статус больше никто не менял. С ADR 0017 заказ закрывают deliverables съёмок, у которых есть настоящий статус работы. Ручной статус стал бы вторым источником правды и расходился бы с реальной работой.

## Решения

### Статус только выводится

- Колонка `deliverables.status` удалена. Форма продукта статус не присылает: поле `status` убрано из `DeliverableDraft`, а лишнее поле Pydantic игнорирует. Селекта Status в Add deliverable формы продукта больше нет.
- Статус заказа собирается из статусов deliverables съёмок, которые его закрывают (`app.shoots.product_deliverables.derived`, SQL):
  1. хоть один отправлен бренду (`approved`) → `approved`: по заказу есть готовый контент;
  2. иначе действует то же правило, что для deliverable съёмки из статусов исполнителей (ADR 0015): `needs_review` → `needs_changes` → `in_progress` → `to_shoot`.
- Без deliverables съёмок статус `to_shoot`.
- Шкала та же, что у deliverables съёмок, поэтому прогресс и чипы на странице продукта (Figma) остаются без изменений.

### Запланирован или нет

- В `DeliverableResponse` появилось поле `shoots`: число съёмок, где заказ закрывает deliverable. Учитываются съёмки любого арт-директора: это прогресс заказа, а не видимость.
- `to_shoot` при `shoots = 0` на фронте показывается как **Not scheduled** (`deliverableStatusChip`). Новый заказ в форме продукта до сохранения тоже Not scheduled.
- Статус есть и в `GET /api/shoots/product-deliverables` (`ProductDeliverableOption.status`).

### Как считается

Статус не хранится, его считает один запрос по `shoot_deliverables` для всех заказов страницы. Так же выводится статус съёмки (ADR 0007). Синхронизировать нечего: статус всегда совпадает с работой.

### Миграция

`upgrade` удаляет колонку. `downgrade` возвращает её и заполняет тем же правилом по связанным deliverables съёмок; заказы без связей получают `to_shoot`.

Демо-данные (`app.demo.seed`): у заказов нет статусов, deliverables съёмок закрывают заказы своего продукта по очереди.

## Не входит в эту итерацию

Бэклог незапланированных заказов у арт-директора, прогресс заказов на карточке в списке продуктов, отдельное «принято брендом» после отправки, запрет удалять заказ, по которому идёт работа.

# 0004. Медиа по ссылке на пост

Статус: принято, 2026-10-06

## Контекст

В модалке Add reference можно вставить ссылку на пост (YouTube Shorts, Instagram Reels, TikTok, Pinterest). По ADR 0003 такой референс хранил только ссылку: превью нет, а пост могут удалить или закрыть. Референсу нужно само медиа.

## Решения

### Сервер скачивает медиа и сохраняет его как обычный файл

`POST /api/uploads/from-link {url}` скачивает видео или картинку поста, проверяет тип по содержимому (как `POST /api/uploads`), кладёт в `files/` и отвечает `{file, platform, title}`. Дальше `file.id` идёт в черновик референса вместе со ссылкой.

Референс со ссылкой может иметь один файл: медиа, скачанное по ней (до этого ADR ссылка и файлы были взаимоисключающими). Не получилось скачать (пост закрыт, платформа просит вход) — референс сохраняется со ссылкой без файла.

Фронт вызывает эндпоинт, как только в поле лежит валидная ссылка, и показывает превью из скачанного файла. Пока идёт скачивание, Add reference заблокирована. Удалили ссылку или вставили другую — прежний файл остаётся неиспользованным (чистка таких файлов — отдельная задача из ADR 0003).

### yt-dlp, ffmpeg и deno из пакетов Python

- Видео качает **yt-dlp**: одна библиотека на все платформы, фиксы под изменения платформ выходят за дни. Версию поднимаем регулярно.
- YouTube больше не отдаёт файлы, где видео и звук вместе: их склеивает **ffmpeg**. Берём статический бинарник из пакета `imageio-ffmpeg`, без apt в образе.
- Без JS-рантайма YouTube отдаёт не все форматы: **deno** из extra `yt-dlp[deno]`.
- Формат: до 1080p, H.264 + AAC в MP4 (VP9/AV1 Safari не играет). Видео до 10 минут и 100 МБ, как у загрузки.
- Посты без видео (пины, картинки в Instagram) yt-dlp не берёт: тогда скачиваем `og:image` страницы поста.

Всё это добавляет к образу около 140 МБ (deno 80, ffmpeg 47, yt-dlp 15).

### Только известные платформы

Сервер не ходит по произвольному адресу из запроса, иначе через ссылку можно достучаться до внутренних сервисов (SSRF). Хост ссылки сверяется со списком платформ, в yt-dlp включены только их экстракторы (без `generic`). Для `og:image` редиректы проверяются вручную: страница только с хоста платформы, картинка только с её CDN (`i.pinimg.com`, `*.cdninstagram.com`, `*.fbcdn.net`), только https.

### Лимиты и ошибки

- 60 скачиваний в час на пользователя.
- Ответы: неизвестный сайт или не медиа — `422`, видео длиннее 10 минут или больше лимита — `413`, платформа не отдала пост — `502`.
- Instagram часто требует вход, а YouTube и Instagram режут адреса дата-центров. Для этого есть `LINK_MEDIA_COOKIES_FILE` (cookies служебного аккаунта) и `LINK_MEDIA_PROXY`.

## Не входит в эту итерацию

Карусели целиком (берём первый элемент), превью-кадр видео на карточке, фоновая очередь скачивания (запрос синхронный, Shorts и Reels качаются за секунды).

# 0016. Арт-директор выбирает любую версию исполнителя

Статус: принято, 2026-10-19

## Контекст

По ADR 0015 арт-директор решал только по последней отправленной версии исполнителя: прежние считались историей. Креатор может отправить несколько вариантов подряд (V1, V2, V3), не дожидаясь решения, и лучшим может оказаться не последний. Арт-директору нужно проверить любой вариант и выбрать один.

## Решения

- Approve и Request changes доступны на любой отправленной версии, пока deliverable не отправлен бренду. Ограничение «только последняя» (409 «A newer version was submitted») снято.
- Approve выбирает версию: у исполнителя одобрена максимум одна. Если у него уже была одобренная версия, с неё снимается решение (`review` и `reviewed_at` обнуляются, feedback остаётся).
- Статус исполнителя считается по всем его версиям (`work_statuses`), а не по последней:
  1. есть одобренная версия → `approved`;
  2. иначе есть отправленная версия без решения → `needs_review`;
  3. иначе (по всем просили изменения) → `needs_changes`;
  4. только черновик → `in_progress`.

  Поэтому Request changes по другому варианту не снимает выбор, а Request changes по выбранной снимает. Версия, с которой ушёл выбор, остаётся без решения и снова ждёт проверки.
- Пока работа исполнителя ждёт проверки (ничего не выбрано, есть версия без решения), «Needs review» / «On review» показывается на каждой его версии без решения: выбрать можно любую.
- Если выбор снят, работа больше не одобрена, и исполнитель снова может загружать версии (ADR 0015 запрещает это только при одобренной работе).

Схема БД не меняется.

## Правка версии после Request changes

- Исполнитель может поправить свою версию, по которой арт-директор попросил изменения: убрать файлы и добавить новые, а потом сохранить. `PUT /api/tasks/{id}/versions/{version_id}/files` присылает итоговый список файлов по порядку: оставленные и новые из `POST /api/uploads`. Убранные файлы удаляются сразу.
- Сохранение снимает решение (`review`, `reviewed_at`), обновляет `submitted_at`, и версия снова ждёт проверки. Feedback остаётся, чтобы арт-директор видел, о чём просил. По правилу выше статус исполнителя становится `needs_review`, даже если по другой его версии всё ещё просят изменения.
- Править можно только версию с Request changes, пока работа не одобрена и deliverable не отправлен бренду; иначе 409. Это меняет правило ADR 0015 «отправленные версии не меняются»: черновик следующей версии по-прежнему тоже доступен.

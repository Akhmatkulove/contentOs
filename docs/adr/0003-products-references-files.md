# 0003. Продукты, референсы и файлы

Статус: принято, 2026-10-04

## Контекст

Бренд создаёт продукт: заполняет поля, добавляет фото и, если нужно, референсы. По кнопке Create product всё сохраняется разом. Референсы при этом попадают в общий пул (страница пула будет позже). Референс, созданный в продукте, получает продукт и его коллекцию, а автором становится бренд.

Фото и референсы — контент брендов, его видят только участники цепочки (ADR 0002). Видео референсов бывают большими.

## Решения

### Файлы загружаются заранее, продукт создаётся одним запросом

1. Каждый файл отправляется отдельно: `POST /api/uploads` (multipart, один файл), в ответ `id`.
2. `POST /api/products` (JSON) получает поля продукта, `photo_ids` и черновики референсов с их `file_ids` или ссылкой. Всё создаётся в одной транзакции: либо продукт со всеми фото и референсами, либо ничего.

Так тяжёлые файлы не едут одним гигантским запросом, загрузку можно показывать по файлам, а создание остаётся атомарным. Загруженный, но не использованный файл остаётся в `files` без привязки; чистка таких файлов — отдельная задача.

Файл может использовать только тот, кто его загрузил, и только один раз (одно фото или один файл референса), иначе `422`.

### Что принимаем

Тип определяется по содержимому файла, а не по расширению или `Content-Type`.

- Изображения JPEG, PNG, WebP до 15 МБ. Pillow перекодирует в WebP, длинная сторона не больше 2560 px, EXIF (в том числе геолокация) удаляется, поворот из EXIF применяется.
- Видео MP4, MOV, WebM до 100 МБ, хранятся как есть. Превью и длительность видео пока не считаем (нужен ffmpeg): карточка видео без превью.
- `POST /api/uploads` — 300 файлов в час на пользователя.

Загрузка идёт через API, а не напрямую в S3 по presigned URL: так проще проверять и перекодировать. Если видео станут больше, перейдём на presigned upload.

### Файлы приватные

Ключи `files/{uuid}.{ext}`, анонимного доступа к ним нет (в отличие от `avatars/`). API отдаёт presigned GET URL на час. Адрес для браузера задаёт `S3_PRESIGN_ENDPOINT_URL`, если API ходит в хранилище по внутреннему адресу (в compose это `minio:9000`).

### Модель

```
files               id, owner_id, key, kind (image|video), content_type, size
products            id, brand_id, name, about, notes, collection, category, sku,
                    status (active|archived), tags[]
product_photos      product_id, file_id (unique), position
references          id, owner_id, product_id?, title?, type?, link?, collection?, notes, tags[]
reference_files     reference_id, file_id (unique), position
```

- Продукт создаёт только одобренный бренд (`require_role(BRAND)`), `brand_id` — он сам. Фото обязательно хотя бы одно.
- Референс — либо файлы (один или несколько, подборка), либо ссылка http(s). Не то и другое сразу и не пусто.
- Референс из продукта: `product_id` — этот продукт, `collection` копируется из продукта на момент создания (у референса в пуле может быть своя коллекция), автор (`owner_id`) — бренд, в интерфейсе показывается его имя. В модалке Add reference поля Product, Collection и Creator видны, но заблокированы.
- Удаление продукта не удаляет референсы: они остаются в пуле с `product_id = null`.
- Коллекция, категория и теги — свободный текст; справочники заведём, когда понадобятся фильтры.

### Интерфейс

Референсы до создания продукта живут в памяти страницы как черновики. По Create product фронт загружает фото и файлы референсов (по три параллельно), затем отправляет продукт. Пока идёт сохранение, кнопка заблокирована.

### Список продуктов

`GET /api/products?search=&page=&per_page=` (до 50 на страницу), новые первыми. Поиск без учёта регистра по названию, SKU и коллекции, `%` и `_` ищутся буквально. В карточке обложка — первое фото (presigned URL). Бренд видит свои продукты, арт-директор — продукты со своими deliverables (ADR 0004), креатор пока видит пустой список.

На карточке статус Active/Archived. Рабочие статусы из Figma (Approved, In progress, To shoot, Needs changes) и прогресс deliverables появятся вместе со съёмками и deliverables. Фильтры Collection, Status и Sort ждут варианта VSelect для фильтров.

## Не входит в эту итерацию

Страница продукта, редактирование, назначение арт-директоров на продукт, превью ссылок, превью и длительность видео, избранное, чистка неиспользованных файлов, страница пула референсов.
